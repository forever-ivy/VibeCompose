# Release evidence

This directory contains non-secret templates for producing a signed,
notarized VibeWhisper build. It contains release-integrity configuration only;
all app capabilities are available without a product-access state.

Keep real credentials outside the repository. Start from
`production.env.example` and provide Developer ID, notarization, Sparkle, and
signed provider-capability values through the release environment.

The release flow is intentionally split:

```bash
scripts/release_signed.sh prepare
scripts/release_signed.sh finalize
```

`prepare` runs the complete check, packages and notarizes the app, generates
the signed update feed and provider policy, verifies Gatekeeper, installs the
candidate, and optionally runs scripted installed-app prechecks. It also writes
`dist/release-candidate-readiness.json`; candidate preparation requires a clean
canonical Git worktree, the optimized Swift release configuration, valid
production URLs, and distinct owner-only Sparkle and provider-policy keys.
Scripted prechecks are not the human acceptance
record. App and DMG notarization each produce an `Accepted` JSON receipt with a
distinct Apple submission ID; both receipts travel with the exact candidate.

Before any public upload, run:

```bash
python3 scripts/verify_release_readiness.py \
  --phase public \
  --output dist/public-release-readiness.json
```

The public phase intentionally fails closed until all of these exist:

- approved, conflict-free `release/brand-clearance.json` no older than 180 days;
- `release/installed-acceptance.json`, copied from the schema-v2 example and
  tied to the exact source commit plus ZIP SHA-256;
- the row-free `release/community-pilot-summary.json` generated by
  `scripts/summarize_community_pilot.py`, with every automated exit gate passed;
- `release/beta-metrics.json`, copied from the schema-v2 example, whose product
  owner review names the exact summary hash, confirms four complete weeks, and
  records zero open P0/P1 blockers;
- `release/public-contact.json`, copied from its example, with approved public
  support, private security-reporting, privacy, and legal contact URLs plus
  responsible roles; the same URLs must appear in the corresponding English
  and Chinese policies, which may no longer describe a private-only Alpha path;
- a clean canonical checkout whose `v<version>` tag points at `HEAD`.

Real raw Pilot rows stay outside the repository. Only the privacy-bounded
aggregate and review record may enter release evidence. Local evidence paths
are ignored by Git and can be overridden with `VIBEWHISPER_INSTALLED_ACCEPTANCE_PATH`,
`VIBEWHISPER_COMMUNITY_PILOT_SUMMARY_PATH`, and
`VIBEWHISPER_BETA_METRICS_PATH`; public contact evidence can use
`VIBEWHISPER_PUBLIC_CONTACT_PATH`. The production GitHub environment supplies
those three JSON files as protected `INSTALLED_ACCEPTANCE_JSON_BASE64`,
`COMMUNITY_PILOT_SUMMARY_JSON_BASE64`, and `BETA_METRICS_JSON_BASE64` secrets
during `finalize`, plus `PUBLIC_CONTACT_JSON_BASE64` for the contact record.

`finalize` repeats the public-readiness gate, verifies the exact prepared
artifacts after publication, and builds a checksum-protected evidence archive.
The archive contains both readiness reports and the exact brand, acceptance,
Pilot aggregate, and Beta review inputs. Signing, notarization, Hardened
Runtime, the two Apple notarization receipts, Sparkle verification, rollback,
and installed-app proof remain
release-integrity controls, not feature or payment gates.

The current committed brand record is `blocked`, no real Community Pilot
evidence has been claimed, and the policies still describe private-Alpha
contact routes. Therefore public finalization is expected to fail; do not
replace those facts with template or synthetic data.

The app must always be verified from `/Applications/VibeWhisper.app`; the
copy under `dist/` is packaging output only.
